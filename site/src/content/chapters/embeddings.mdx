<Step title="Each token becomes a list of numbers" map="embedding">

<NumberStrip text="Lily wanted to play with her" />

<Level of="story">

An id like 665 is only a label, and its size means nothing. So each id picks one row from a big table, a list of 128 numbers called an <Term id="embedding">embedding</Term>. A token gets the same list every time it appears.

These numbers start out random. Training nudges them, bit by bit, until they help the model guess well. Tap a cell to see one number.

</Level>

<Level of="numbers">

The table has 4,096 rows, one for each token, and 128 numbers in each row. That is 524,288 numbers, about 2 in every 5 numbers the model learned.

The first five numbers for "Lily" are 0.008, 0.006, -0.046, 0.001 and -0.209. A list of numbers like this is called a <Term id="vector">vector</Term>.

</Level>

<Level of="formula">

Looking up a row of the embedding table <Tex tex="W_E" /> gives the token's vector.

<Tex display tex="\mathbf{x}_i = W_E[t_i], \qquad W_E \in \mathbb{R}^{4096 \times 128}" />

The lookup is the same as multiplying a one-hot vector, all zeros except a 1 at <Tex tex="t_i" />, by <Tex tex="W_E" />.

</Level>

<Level of="code">

```ts
const lily = rowView(model.wte, 665); // 128 numbers
trace.tokenEmbeddings; // one row per token, 6 × 128
```

</Level>

</Step>

<PredictReveal question="Which word has numbers most like &quot;happy&quot;?" options={['glad', 'sad', 'tree']} answer={0}>

"Glad", with a similarity of 0.61 out of 1. But "sad" is not far behind at 0.49. Words that show up in the same kinds of sentences get similar numbers, even when they mean opposite things.

</PredictReveal>

<Step title="Similar words get similar numbers">

<NearestTokens words={[' girl', ' ran', ' red', ' happy', ' dog', ' mom', ' Lily', ' three']} />

<Level of="story">

Nobody tells the model what words mean. Still, after training, words used in similar ways end up with similar lists (<Ref id="mikolov2013" />). "Girl" lands near "boy", "red" near the other colors, and "ran" near "run" and "walked".

The model found this on its own, because it helps to guess the next word. Pick a word to see its closest tokens.

</Level>

<Level of="numbers">

The score is the cosine similarity. 1 means the two lists point the same way, 0 means they have nothing in common and -1 means they point opposite ways.

"·girl" and "·boy" score 0.74. "·three" and "·3" score 0.88, so the model uses the word and the digit almost alike. ("·3" is one of the few numbers with a token of its own.) "·Lily" and "Lily" at the start of a text score 0.76, even though the Tokens chapter showed they are two different tokens.

</Level>

<Level of="formula">

Cosine similarity divides the <Term id="dot-product">dot product</Term> of two vectors by their lengths, so only their direction counts.

<Tex
  display
  tex="\cos(\mathbf{a}, \mathbf{b}) = \frac{\mathbf{a} \cdot \mathbf{b}}{\lVert \mathbf{a} \rVert \, \lVert \mathbf{b} \rVert}"
/>

</Level>

<Level of="code">

```ts
const dot = (a, b) => a.reduce((sum, x, k) => sum + x * b[k], 0);
const cosine = (a, b) => dot(a, b) / Math.sqrt(dot(a, a) * dot(b, b));
cosine(rowView(model.wte, 477), rowView(model.wte, 497)); // ·girl and ·boy, 0.74
```

</Level>

</Step>

<Callout kind="analogy" title="Like places on a map">

Think of each word as a town on a map, with towns that are used alike sitting close together. **Where this breaks.** A map has 2 directions. These lists have 128, and single numbers rarely mean anything simple on their own, like size or color.

</Callout>

<Step title="Comparing two lists">

<Level of="story">

To compare two lists, multiply the numbers in matching places and add up the results. This is the <Term id="dot-product">dot product</Term>.

It is big when both lists have large numbers in the same places with the same signs. It is near zero when they have nothing in common, and below zero when the signs disagree. The dot product comes back in the attention chapter, where it decides which tokens look at which.

</Level>

<Level of="numbers">

Take (1, 2, 3) and (4, 0, -1). Multiply place by place to get 4, 0 and -3. Add them up to get 1.

</Level>

<Level of="formula">

<Tex display tex="\mathbf{a} \cdot \mathbf{b} = \sum_{k=1}^{d} a_k \, b_k" />

For our embeddings <Tex tex="d = 128" />.

</Level>

<Level of="code">

```ts
const dot = (a, b) => a.reduce((sum, x, k) => sum + x * b[k], 0);
dot([1, 2, 3], [4, 0, -1]); // 1
```

</Level>

<Exercise prompt="What is the dot product of (2, -1, 3) and (1, 4, 2)?" answer={4} tolerance={0}>

Multiply place by place to get 2, -4 and 6. Add them up to get 4.

</Exercise>

</Step>

<Step title="Each place gets numbers too" map="position">

<Level of="story">

So far, "play" gets the same list wherever it appears. But order matters. "Lily saw Max" and "Max saw Lily" use the same words.

So the model also learns one list of 128 numbers for each place in the text, called a <Term id="position-embedding">position embedding</Term>. It adds the place's list to the token's list, number by number. That sum is what the first layer reads.

</Level>

<Level of="numbers">

Our model has 128 position lists, one for each place, so it reads at most 128 tokens at a time. Nearby places get similar lists. Places 2 and 3 score 0.98, while places 2 and 51 score -0.22.

Our model learns these lists, like GPT (<Ref id="radford2018" />) and GPT-2. The original transformer used fixed sine and cosine waves instead (<Ref id="vaswani2017" />).

</Level>

<Level of="formula">

<Tex display tex="\mathbf{h}_i = W_E[t_i] + W_P[i-1], \qquad W_P \in \mathbb{R}^{128 \times 128}" />

Places count from 1 but table rows count from 0, so place <Tex tex="i" /> uses row <Tex tex="i-1" />.

</Level>

<Level of="code">

```ts
trace.positionEmbeddings; // one row per place, 6 × 128
trace.embeddings; // tokenEmbeddings + positionEmbeddings
```

</Level>

</Step>
